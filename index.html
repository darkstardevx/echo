The payload viewer
WraithFlow never had.

WraithFlow captures traffic — but until now, it only ever went to stdout, which under systemd means journalctl and nothing else. Echo tails WraithFlow's capture_log and gives you an actual flow list: scroll, filter, inspect, follow live or pause to browse history.

Browse, not just tail

An actual flow list.
Not a scrollback buffer.

WraithFlow gained one small addition for this: an optional capture_log config field that writes every logged packet to a shared JSONL file alongside its normal stdout output.

Echo tails that file and turns it into something you can actually browse — not just scroll back through terminal history hoping the line you want hasn't scrolled off.

wf-echo
live
$ wf-echo

http-traffic-gateway   14:32:08   2.1 KB
secure-db-relay        14:32:09   640 B
http-traffic-gateway   14:32:11   14.8 KB
http-traffic-gateway   14:32:14   1.2 KB

j/k move · / filter · enter detail · f follow/pause

Follow live.
Or scrub back through it.

Press f to toggle between following new flows as they land, or pausing to browse everything already captured — the same tab, no separate mode to learn.

wf-echo --list dumps every captured flow as JSON, for scripting — no TUI required.

wf-echo --list
json
$ wf-echo --list | jq '.[0]'

}
Zero-config setup

Nothing to configure
in Echo itself.

Echo reads capture_log straight from WraithFlow's own config — one field, in one place. If it isn't set yet, Echo tells you exactly that, rather than just silently showing nothing.

~/.config/wraithflow/config.toml
config
# add this line, then restart wraithflow
capture_log = "~/.local/state/wraithflow/captures.jsonl"

Get Echo running

One command — downloads, verifies the checksum, installs to ~/.local/bin.

>_ curl -fsSL https://raw.githubusercontent.com/darkstardevx/echo/main/install.sh | sh

Installs wf-echo. Needs WraithFlow already installed and its capture_log configured — see above.
